# 13 协作与云服务

相关目录：`app/src/core/service/collaboration/`

```text
collaboration/
  CollaborationService.tsx   # 主服务：房间、同步、状态机
  CollabProtocol.ts          # 消息协议类型
  CollabTransport.ts         # WebSocket 传输 + 地址推导
  CollabApi.ts               # HTTP API（创建/加入房间）
  stageMap.ts                # 舞台文档映射 + jsondiffpatch 差分
```

## 1. 整体模型

```text
服务端（Graphif 云）：
  REST  /api/collab/rooms      创建房间（携带初始 stage/tags/references）
  REST  /api/collab/rooms/join 邀请码加入
  WS    /ws                    auth → join → op 同步
客户端（CollaborationService）：
  stage 序列化 → StageMapDoc（objects + order）
  jsondiffpatch 计算 delta → 发送 op { baseVersion, delta, opId }
  服务端按版本号接收，冲突时 reject（返回最新文档全量）
```

## 2. stageMap（文档模型）

- `StageMapDoc = { objects: Record<uuid, serialized>, order: string[] }`；
- 内部引用（serializer 的 `{$: path}`）转换为 `{$u: uuid}`，避免数组路径在 map 中失效；
- `diffStageMap(left, right)` / `patchStageMap(doc, delta)`：jsondiffpatch（objectHash 按 uuid、detectMove）；
- `stageArrayToMap / stageMapToArray`：与工程 `serialize()` 输出互转。

## 3. CollabProtocol（协议）

客户端 → 服务端：

```text
{ type: "auth", token }
{ type: "join", roomId }
{ type: "op", baseVersion, delta, opId }
{ type: "ping" }
```

服务端 → 客户端：

```text
joined（全量文档 + members + presences + you）
op（版本化增量广播）
reject（baseVersion 冲突，可携带最新全量）
presence（join/leave）
member（兼容旧服务端）
error / pong / auth_ok
```

角色：`owner / editor / viewer`；成员按账号持久，presence 按 session（同用户多端各一行）。

## 4. CollaborationService

状态机：`idle → connecting → synced → disconnected / error`。

关键行为：

- `createRoom()`：需登录 → 上传当前舞台快照 → 连 WS；
- `joinRoom(inviteCode)`：新建 `collab:` URI 的 Project → 加入 → 服务端注入文档；
- `onLocalCommit`：监听 `stage-commit` 事件，计算 delta 发送 op，维护 `ackMap`/`inFlightOpId`，失败重发（dirty 标记）；
- 远端 op：`applyStageMap`（`applyingRemote` 防回环）→ 反序列化替换舞台 → `updateReferences()` → `clearHistory()`（协作场景禁用本地撤销）；
- `leave()/dispose()`：断开 WS 并清理；
- `canEdit`：owner/editor 可编辑；viewer 只读；
- 状态通过 `collab-state` / `collab-status` 事件广播，`sub/CollaborationWindow.tsx` 展示。

## 5. 传输与地址

`CollabTransport`：

- `resolveCollabHttpBase()`：优先 `LR_COLLAB_BASE_URL`，否则由 `LR_API_BASE_URL` 推导（localhost:3000 → :3100，hub./api. 子域 → collab. 子域）；
- `resolveCollabWsUrl(token)`：`ws(s)://<base>/ws?token=...`；
- 心跳：20s ping（服务端 60s 超时）；
- 消息 JSON 解析失败静默忽略。

## 6. 认证（AuthClient / UserState）

- `AuthClient.tsx`：better-auth 客户端（`/api/auth/*`），`FeatureFlags.USER`（存在 `LR_API_BASE_URL`）时初始化；
- `UserState`：`user.json`（Tauri store）持久化 `{ user, token }` 会话；启动时校验 session 有效性，失效则清理；
- `main.tsx` 的 `initAuth()` 恢复 `currentUserAtom`；
- `sub/SettingsWindow/account.tsx`：登录/注册/个人资料 UI。

## 7. 遥测（Telemetry）

- `Telemetry.tsx`：事件上报（启动、错误、关闭应用等）；
- 由 `FeatureFlags.TELEMETRY`（即配置了云 API 地址）控制；
- 上报前收集系统信息（`get_device_id`、`cpuInfo`、OS 发行版等）。

## 8. 特性开关（FeatureFlags）

```ts
USER / AI / TELEMETRY = "LR_API_BASE_URL" in import.meta.env
```

未配置云地址时：登录、协作、AI、遥测整体降级为禁用（设置页隐藏相关项）。

## 9. 其他云能力

- `SubWindowOpenModes` 等设置不涉及网络；
- 更新：Tauri updater（`release.project-graph.top` 端点）与 `utils/updater.tsx`；
- 账户相关：`sub/SettingsWindow/account.tsx`（登录态、设备管理预留）。
