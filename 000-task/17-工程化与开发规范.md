# 17 工程化与开发规范

## 1. Monorepo 与包管理

- pnpm workspace：`app` + `packages/*`；
- catalog 版本统一（react 19、typescript 5.9、jotai 2、vitest 4、tsdown 0.21）；
- Nx（22.x）：`nx.json` 定义 target 依赖与缓存：
  - `build` 依赖 `^build`，输出 `dist/**`，缓存；
  - `dev` / `tauri:dev`：continuous，不缓存；
  - `tauri:build` 依赖前端 build；
  - `type-check` 缓存（仅 src 输入）；
  - `publish` 依赖 build；
  - `defaultBase: next`。

根 `package.json` 脚本：

```text
dev            nx run-many -t dev tauri:dev
build / build:ci / build:no-tauri / tauri build（Agent 禁止执行）
lint / lint:fix（eslint）
format         prettier --write .
test           vitest
tauri          pnpm --filter @graphif/project-graph tauri
publish        nx run-many -t publish
```

## 2. 质量工具

- ESLint 10 + typescript-eslint + eslint-plugin-react + prettier（`eslint.config.js`）；
- Prettier + Tailwind 插件（`.prettierrc`）；
- Husky + lint-staged（提交前 lint/format 暂存文件）；
- Vitest：`vitest.config.ts` 只包含 `app/src/**/*.test.{ts,tsx}` 与 `packages/*/tests/**/*.test.{ts,tsx}`，测试文件与源码同目录（core 内大量 `*.test.ts`，packages 有独立 `tests/`）；
- 类型检查：`pnpm --filter @graphif/project-graph type-check`（`tsc --noEmit`）。

## 3. 类型检查 Skill

改代码后的验证统一走 `.agents/skills/type-check`，**禁止运行 build / tauri build**（AGENTS.md 明确约束）。

## 4. i18n 工作流

- 新增文案：改 `en.yml` / `zh_CN.yml`（及需要时的 `zh_TWC.yml`、`id.yml`）；
- **禁止手改 `zh_TW.yml`**：由 `app/scripts/sync-locales.ts`（OpenCC）生成；
- Vite 插件 `i18n-auto-tw` 在构建/开发时自动转换 zh_CN → zh_TW。

## 5. 目录与命名约定

- 目录内使用 `something.tsx`，不用 `index.tsx`（core 内明显遵循；SettingsWindow 等少数 UI 目录例外）；
- 优先在已有文件实现功能，避免拆成大量小文件；
- 注释规范：不写组织性/总结性注释，只解释不直观的 why。

## 6. 错误处理规范

前端：

- 禁止 `catch {}` 或仅 `console.error` 后忽略；
- 能不 catch 就不 catch，让调用方处理；
- 必须提示时用 Dialog/toast（用户看不到控制台）；
- 错误向上传到 `window`，由 ErrorHandler/Fallback 展示。

Rust：

- Tauri 命令内部妥善处理错误并返回给前端（`Result<_, String>`），禁止未捕获 panic。

## 7. Agent 约束（工作区内开发）

- 禁止用 shell 在 `node_modules` 搜索/翻源码，依赖用法查官方文档或 skill；
- 禁止用 python/node -e/内联脚本做文本处理或批量改文件；
- 禁止 build 类命令；
- 快捷键/设置改动分别遵循 `create-keybind`、`create-setting-item` skill；
- UI 改动遵循 `shadcn` / `ui` skill；图标建议用 `suggest-lucide-icons`；
- 提交信息使用 Conventional Commits（`feat:` / `fix:` / `refactor:` …）。

## 8. 测试与发布

- `pnpm test`（vitest run/watch）覆盖：TabGroup 布局、序列化、数据结构、形状、AI 会话/技能/MCP 配置等；
- 包发布：`pnpm publish` 前置 `build:no-tauri`；
- 更新器：Tauri updater 端点 `release.project-graph.top`。
