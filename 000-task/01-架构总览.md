# 01 架构总览

## 1. 系统定位

Project Graph 是一款桌面级节点图绘制工具，面向头脑风暴、知识图谱、项目规划等可视化思考场景。应用形态是桌面程序（Windows / macOS / Linux，另有 Android/iOS 生成骨架），业务主体运行在 WebView 前端，Rust 只承担文件系统与系统级能力。

仓库 GitHub：`graphif/project-graph`。

## 2. 技术栈

| 层       | 技术                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| UI       | React 19 + TypeScript、Tailwind CSS 4、shadcn/ui（Radix 封装）、Lucide 图标                                 |
| 富文本   | Plate（platejs / @platejs/\*，Slate 内核），Vditor 面板                                                     |
| 状态     | Jotai（单一 `store` + 派生 atom）                                                                           |
| 画布     | Canvas 2D（自研三层渲染器）；SVG 导出；DOM 叠加输入层                                                       |
| 桌面壳   | Tauri 2（Rust），WebView2/WKWebView/WebKitGTK，Linux 可选用自研 CEF runtime                                 |
| 数据格式 | `.prg` = ZIP 容器，内部为 MsgPack（stage/tags/references/metadata/README/attachments/thumbnail）            |
| 序列化   | `@graphif/serializer`（reflect-metadata 装饰器 + 引用路径）                                                 |
| 构建     | pnpm workspace + Nx；Vite 8；tsdown（包）；esbuild（扩展）                                                  |
| AI       | AI SDK（`ai` v6）+ OpenAI Compatible provider；MCP（`@ai-sdk/mcp` + Rust `rmcp` stdio）；Skills（SKILL.md） |
| 协作     | WebSocket 自研协议 + stageMap 差分（jsondiffpatch）                                                         |
| 扩展     | `.prg` 扩展包 + Web Worker + Comlink 通信，`extprg` CLI 工具链                                              |

## 4. 核心抽象：Tab 与服务容器

系统最重要的设计是 **“标签页 = 可运行容器”**：

- `Tab`（`app/src/core/Tab.tsx`）本身是 React 组件基类，同时持有：
  - `services: Map<serviceId, Service>` — 服务注册表；
  - `fileSystemProviders: Map<scheme, FileSystemProvider>` — 按 URI scheme 的文件访问；
  - rAF 主循环 `loop()/pause()/tick()`，按 `Settings.maxFps` 节流驱动所有 `tickableServices`；
  - EventEmitter 事件（`state-change`、`contextmenu`、`stage-commit`、`collab-state` 等）。
- `Project`（工程）是 `Tab` 的主要子类，一个标签页对应一个 `.prg` URI；通过 `@service("id")` 装饰器 + `loadService` 注册服务，服务实例会以 `project.<id>` 形式直接挂在工程上（TypeScript 通过 `declare module` 补全类型）。
- `ComponentTab` 是纯 UI 子窗口/面板标签，承载 React 内容，无业务服务。

服务生命周期：

```text
Tab 构造
  → registerFileSystemProvider(file|draft|collab)
  → loadAllServicesBeforeInit(project)    // 大部分业务服务
  → project.init()                        // 解析 .prg、反序列化舞台
  → loadAllServicesAfterInit(project)     // HistoryManager、CollaborationService
  → TabWorkspace.open(tab)                // 加入 tabsAtom 并聚焦
  → tab.loop()                            // rAF 循环驱动 tick
  → TabWorkspace.close(tab) → tab.dispose()  // 逐个 dispose 服务
```

## 5. 启动流程（`app/src/main.tsx`）

1. 读取 Tauri CLI 参数，判断是否为 CLI 模式（`--output` 出现即 CLI）。
2. 并行初始化全局单例：`RecentFileManager`、`StartFilesManager`、`ColorManager`、`Tutorials`、`UserState`、`QuickSettingsManager`、`ExtensionManager`。
3. 并行加载：i18n 语言文件（5 种语言）、同步模块（`EdgeCollisionBoxGetter`、`MouseLocation`）、认证恢复（`initAuth`）。
4. 渲染 `App`（Jotai Provider + ErrorBoundary + Toaster）。
5. 加载启动文件（CLI 参数路径 / 待打开文件队列 / macOS 双击 / deep link `prg://`）。
6. 无标签页时创建空白草稿并弹出欢迎窗口。

## 6. 模块依赖方向

- `core/stage` 只依赖 `core/service`（如 Settings、特效）和 packages，不依赖 React UI 组件；
- `core/render` 依赖 `core/stage`（读 StageObject 数据）与 `core/service`（Settings、MouseLocation）；
- `core/service` 中的控制器/管理器通过 `project.xxx` 访问其他服务，形成“服务协作网络”；
- `core/extension` 依赖 `core/service`（Settings、KeyBindsUI）与 `core/stage`（ExtensionEntity）；
- UI 层（`components`/`sub`）只调用 `TabWorkspace`、全局服务与 `project` 实例方法，不直接操作 Canvas；
- Rust 层完全被前端调用（`invoke`），不反向依赖前端。

## 7. 关键设计模式

| 模式                  | 应用位置                                                                            |
| --------------------- | ----------------------------------------------------------------------------------- |
| 服务定位器 / 依赖注入 | `Tab.loadService`、`Project.<serviceId>`、`@service` 装饰器                         |
| 组合模式              | 特效 `Effect` 子特效树；标签页布局 `TabGroupNode`（group/split 树）                 |
| 装饰器 + 反射序列化   | `@serializable`、`@id`、`@passObject` 等（`@graphif/serializer`）                   |
| 观察者                | Tab EventEmitter、`Settings.watch`、`KeyBindsUI` 订阅                               |
| 策略模式              | 导入/导出（BaseImporter/BaseExporter 子类）、边渲染器（Straight/Symmetry/Vertical） |
| 命令模式（简化）      | 快捷键表 `allKeyBinds` + `KeyBindsUI.execute`                                       |
| 代理模式              | Comlink `proxy(project)` 把 Project 暴露给扩展 Worker                               |
| 差分同步              | 协作 `stageMap` + jsondiffpatch（服务端权威版本号 + 拒绝重放）                      |

## 8. 环境变量开关

Vite 仅注入 `LR_` 前缀环境变量（`envPrefix: "LR_"`）：

| 变量                 | 作用                                                            |
| -------------------- | --------------------------------------------------------------- |
| `LR_API_BASE_URL`    | 云 API 地址；存在时开启用户/云/AI/遥测特性（见 `FeatureFlags`） |
| `LR_COLLAB_BASE_URL` | 协作服务地址（默认由 API 地址推导，开发环境 localhost:3100）    |

## 9. 跨端差异处理

- `app/src/utils/platform.ts` 提供 `isDesktop / isMobile / isWeb / isMac / isWindows / isLinux`；
- Rust 层按平台条件编译命令（`get_device_id`、`get_distribution`、CEF runtime、移动端入口）；
- 快捷键跨平台转换（`utils/emacs.ts` 的 Win→Mac 转换）；
- 窗口装饰、关闭按钮、全局快捷键按平台差异化实现。
